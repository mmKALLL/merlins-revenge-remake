# Engine mechanics: combat (Merlin's Revenge original Lingo source)

Source root (abbreviated `casts/` below):
`assets-mr-original/merlin_open_30_speedy_and _tvs/casts/`
Conventions as in `engine-mechanics-walking-and-rooms.md` (30 Hz tick, 32 px tiles, `file:line` references). This note covers the next slice: goblin warrior (melee) + goblin archer (ranged), spawning, AI, damage, the energy blast spell, reeling, death and exit gating.

## 1. Actor data inheritance

Actor definitions are text/field members of the `data` cast named `act_<symbol>` (e.g. `casts/data/act_goblinWarrior.txt`), each a Lingo property list. `actorMaster.retrieveActorData(typ)` (`master_objects/actorMaster.txt:126-142`) resolves them:

```
dataObj = g.collectionsMaster.getObj(#objActorData, datatyp); data = dataObj.getData()
if data[#inherit] <> void then
  inheritData = me.retrieveActorData(data.inherit)          -- recursive
  data = ListsMerge(inheritData.duplicate(), data)          -- child props overwrite parent props (actorMaster.txt:133)
end if
if data[#attack] <> #none and data[#attack] <> void then
  attack = g.structMaster.getStruct(#attack)                -- defaults from structMaster.structAttack
  data.attack = ListModifyProperties(attack, data.attack)   -- (actorMaster.txt:139)
end if
```

- `ListsMerge` (`general_functions/ListsMerge().txt:9-14`) is a **shallow** top-level overwrite: a child's `#attack` sub-list *replaces* the parent's `#attack` wholesale (it is not merged). E.g. `act_goblinArrow`'s `#attack` replaces `act_bullet`'s `#attack` (so `#hits` for the arrow comes from the struct default `[#teamMembers]`, not from act_bullet -- same value by coincidence).
- `ListModifyProperties(params, data)` (`general_functions/ListModifyProperties().txt:4-13`) is **recursive** for prop-list values: used both to overlay the actor's `#attack` on top of `structAttack` defaults, and (in `actorMaster.setParamsFromData`, `actorMaster.txt:280-285`) to overlay the *whole* resolved actor data onto the object's `getParams(#init)` defaults. Unknown keys are simply added to the object's param list.
- So the precedence is: **object/module default params** (`objGameObject`, `objCharacter`, `objCPUCharacter`, and each `mod*.addModParams`) < `act_actor` < `act_character` < `act_CPUCharacter` < `act_goblinWarrior`. For `#attack` sub-lists: `structAttack` defaults < the innermost data file that defines `#attack`.

Chains: `goblinWarrior -> CPUCharacter -> character -> actor`; `goblinArcher` same; `player -> actor`; `goblinSword -> weapon -> actor`; `goblinBow -> weapon -> actor`; `goblinArrow -> bullet -> actor`; `energyBlast -> actor` (the spell scroll); its bullet `#energyBlastBullet` has **no `act_` file** -- see section 5.

## 2. Spawning from the objects layer

- When a room activates the first time, `objRoom.activate` (`script_objects/objRoom.txt:110-135`) calls `g.teamMaster.setRoomClear(false)`, `addPlayerToRoomObjects()`, then `me.activateActors()` (only `if pBeenActivated = false`; later visits call `restoreState()` + `reDrawGraves()`), then `attemptOpenExits()`.
- `objTileLayer.activateActors` (`objTileLayer.txt:160-187`) walks the **objects layer** entries in order (`peekEntryNo(i, tileLoc)` -> 1-based `(col,row)`, `objDataMap.txt:119-131`), maps the tile number to a key symbol (`getTileSymbolByNum`), and for every symbol `<> #none`:

```
objectLoc = tileLoc * tileSize + mapLocation          -- objTileLayer.txt:179 (tileLoc is 1-based!)
params = g.actorMaster.getParams(#newActor); params.typ = nSymbol; params.startLoc = objectLoc
nObj = g.actorMaster.newActor(params)                 -- objTileLayer.txt:180-183
```
  `mapLocation = pRoom.getSpriteLoc()` (the room sprite's top-left on stage). Because `tileLoc` is 1-based, `tileLoc*32` is the **bottom-right corner** of the tile; `actorMaster.startActor` then adds `params.startOffset` (`actorMaster.txt:205-207`: `if useOffsets then startLoc = startLoc + params.startOffset`; `useOffset` defaults true, `actorMaster.txt:26`), and `act_actor` sets `#startOffset: point(-16,-16)`, so **actors spawn with their reg point at the tile centre**. `#player` is skipped if a player already exists (`objTileLayer.txt:175-177`).
- `actorMaster.newActor` (`actorMaster.txt:53-64`) first requires a free sprite (`g.spriteMaster.checkFreeSprite()`), then `startActor(typ, startLoc, useOffset, initVect, preBuilt, forceCreate, startActor)` (`actorMaster.txt:181-265`):
  1. `actorData = retrieveActorData(typ)` (section 1); `obj = g.objectMaster.requestObject(actorData.objType)`.
  2. If `actorData.AiType <> void`: `AI = requestObject(AiType)`, `AI.init(AI.getParams(#init))`; only for `#objAiEnemyTargetSeek` it also calls `setTargetType(actorData.AiTarget)` / `setAction(actorData.AiTargetAction)` (`actorMaster.txt:189-197`) -- the old hair-seeking AI, **not used by goblins**.
  3. `params = obj.getParams(#init)` overlaid with the actor data (`setParams`/`setParamsFromData`, `actorMaster.txt:267-285`), `params.AI = AI`, `params.initLoc = startLoc` (after offset), `params.initVect` if given, `params.actorType = typ` when it was `#typ` (`actorMaster.txt:218-220`), `masterPrg` resolved to the actorMaster instance; `obj.init(params)`.
  4. Placement check (`actorMaster.txt:226-246`): unless `params.createOnSolid or forceCreate`, and only if `obj.getCollisionDetection()`, it runs `g.collisionMaster.checkCollisionsNewObject(obj)` (hard-edge overlap) and `checkCollisionsWithSolidArea(startLoc)` (`actorMaster.txt:73-85`: the active tile under `startLoc` must not be `#solid` or `#outsidePlayArea`). If either fails, `obj.finish()` and `#none` is returned -- the actor silently does not spawn. Bullets have `createOnSolid: true` so they always spawn.
  5. `obj.start()` (if `startActor`), and `pPlayer = obj` for `#player`.
- **Team assignment** happens in `objGameObject.init` (`objGameObject.txt:137-140`): after `ancestor.init(params)` it calls `me.joinTeam()` -> `g.teamMaster.joinTeam(pTeam, pTeamRole, me.ID.bigMe)` (`objGameObject.txt:610-612`), where `pTeam` = data `#team` (`#goblins` for both goblins; `#aldevar` for the player; bullets `#none`) and `pTeamRole` = `#teamMembers` by default (`objGameObject.txt:72`; bullets `#teamBullets`). `teamMaster.joinTeam` (`teamMaster.txt:1213-1227`) appends the object to `pTeams[team][role]`, tells `reservationsMaster`, `addObjectToCurrentRoom(obj)` and `obj.linkIn()` (registers the object in the per-tile unit map used for target search, section 3). `objGameObject.finish` calls `leaveTeam` (`objGameObject.txt:146-149`).
- Team definitions are `data/tem_*.txt` members (collectionsMaster prefix `"tem"`, `collectionsMaster.txt:21`). `tem_goblins.txt:3-8`: `#teamName: #goblins, #category: #enemies, #colour: rgb(0,255,0), #friends: [orcs], #hates: [[#aldevar, #monsterSummon, #karate, #magicalAlliance, #ninja, #undead, #scarlet, #village]], #maxMembers: 16`. `tem_aldevar.txt:3-8`: `#teamName: #aldevar, #category: #friends, #friends: [#village, #monsterSummon], #hates: [[#blackSorcerer, #scarlet, #cave, #goblins, #karate, #ice, #magicalAlliance, #monsters, #ninja, #swamp, #undead, #orcs], [#pitMonsters, #invisible, #collectables]], #maxMembers: 12`. `#hates` is a **priority list of lists**: `hates[1]` is the first-priority group. "Enemies of X" = `calcTargetTeamsByAllegiance(obj)` (`teamMaster.txt:136-157`): for `targetAllegiance #enemy` (structAttack default) it is `team.hates.duplicate()`; for `#friendly` it is `[friends + own team]`.
- **"Resident"** in this engine means a unit *contained in a dwelling* (goblin huts etc.): `modResidents` (`script_objects/modResidents.txt:2`: "used by any game object that needs to periodically release residents") holds `residentGroups` and spawns them with `g.actorMaster.newActor` from `releaseResident` (`modResidents.txt:146-171`). It is not needed for the objects-layer spawn of a plain goblin. `structAttack.residentTeamCategory` is likewise only for summon spells. (`recordInRoomState` is the separate flag that makes an object part of the room's saved state when you leave a room -- true by default, false for arrows.)

## 3. Enemy AI per tick

Class chain: `objAiCPU -> objAiAttack -> objAi` (`objAiCPU.txt:13`, `objAiAttack.txt:8`); `objAiCPU` adds the module `modPathFinding` (`objAiCPU.txt:15`). `objAiEnemyTargetSeek` (`objAiEnemyTargetSeek.txt`) is the older `objAiEnemy` hair-seeking AI (`pTargetType #playerHair`, `#attach` action); it is only wired when an actor's `AiType` is `#objAiEnemyTargetSeek`, which no goblin uses, so it can be ignored.

The AI has its own mode (`me.pMode`) separate from the character's mode (`pCharacterPrg.pMode`, the animation/physics state: `#stand/#walk/#weaponMelee/#weaponRanged/#charge/#release/#reel/#die/#dead/#finish/#look...`). Per tick (`objAiCPU.update`, `objAiCPU.txt:444-468`, then `objAiAttack.update`, `objAiAttack.txt:376-387`):

```
#findTarget:   fin = updateFindTarget();   if fin then goMode(#moveToAttack)
#moveToAttack: finState = updateMoveToAttack(); #noTarget -> clearTarget, goMode(#findTarget); #fin -> attack()
#runReload:    fin = updateRunReload();     if fin then goMode(#moveToAttack)      (only if runReload true; goblins: false)
#attack:       updateAttack()      -- objAiAttack.txt:389-414
#release:      updateRelease()     -- objAiAttack.txt:416-420
#dazed:        nothing (set while character is #dazed/#dead/#die/#finish/#look/#recoil/#reel/#reelFly/#reelLanded/#reelSit,
               objAiCPU.characterModeChanged objAiCPU.txt:116-135; leaving those modes -> #findTarget)
```

**Target selection** (`refreshTarget`, `objAiCPU.txt:273-314`; also re-run every 30 ticks while chasing: `pRetargetCounter.tim[2] = 30`, `objAiCPU.txt:23-24`, `updateRetargetCounter` `objAiCPU.txt:545-553`, and whenever the target dies/leaves): `closestTarget = g.teamMaster.findTarget(me.pCharacterPrg)` (`teamMaster.txt:867-919`):
1. `hatedTeams = calcTargetTeamsByAllegiance(obj)` (the `#hates` priority list), then `targetTeams = cullTeamList(hatedTeams[1])` (`teamMaster.txt:173-194`): keeps first-priority teams that have `teamBuildings.count + currentMembers > 0`; **if the total alive across them is < 5 (or none), `#none` is prepended**.
2. If `targetTeams[1] = #none`: with no other teams the result is empty (no target); otherwise `findATarget(obj, hatedTeams)` (`teamMaster.txt:691-742`) does a full scan: for each priority group, for each team, `findTargetInTeam(team, objLoc, targetCriteria, targetRoles)` (`teamMaster.txt:744-809`) iterates `targetRoles` (default `[[#teamMembers, #teamBuildings]]`) skipping dead objects, and with `targetCriteria #closestDistance` picks the minimum `GeomDistSqr(theLoc, nLoc)` (squared Euclidean distance between reg points; `#lowestHealth` uses `getHealth()`). It returns a `structTeamTarget` `[#obj, #dist (=999999 initially), #priorityRank]` (`structMaster.txt:890-896`), `dist` square-rooted at the end (`teamMaster.txt:738-740`). `#collectables` is removed from the candidate teams (`teamMaster.txt:723`).
3. Otherwise (>= 5 enemies alive) it uses the per-tile **unit map**: `tileLoc = getTileLoc(objLoc)` (`teamMaster.txt:78-102`: `point((x - playArea.left)/32 + 1, (y - playArea.top)/32 + 1)` clamped to the room), then `searchUnitMap(tileLoc, targetTeams, 0, 20)` (`teamMaster.txt:1421-1528`) scans square shells of tiles outward (shell 1..20, capped at 50) until the first shell with any hit, collecting objects of the target teams from the linked `objMapNode` lists; then the closest by `GeomDistSqr` among those, filtered by `targetRoles[1][1]` if only one role is listed. (So with few enemies the search is global; the tile search is an optimisation, not a range limit.)
- On success: `formRelationship(newTarget, #target, #exclusive)`, `keepMePosted(newTarget, #leaveGame, #once)`, `setMultiAttack(pMultiAttack, pBufferDist)` (`objAiCPU.txt:300-303`). On failure: `moveToLoc(#none)` and, if `isTargetsDead` or `getRoomClear`, the internal event `#noTargetFound` -> `cancelAttack` (`objAiCPU.txt:304-313`, `232-237`).
- `eyestrain` is **not** used in target selection; it is aiming inaccuracy for ranged/magic attacks (below).

**Movement toward the target** (`updateMoveToAttack`, `objAiCPU.txt:495-529`): each tick, if the target is gone/dead -> `#noTarget`; `targetInReach()` (`objAiCPU.txt:350-377`) -> if `#fin` fire `#arrivedAtAttackLoc` (stops movement: `modPathFinding.txt:79-81`) and return `#fin` (-> `attack()`); else `idealAttackLoc = calcIdealAttackLoc(targetLoc)` and `me.findPathToLoc(idealAttackLoc)`.
- `calcIdealAttackLoc` (`objAiAttack.txt:75-94`): for `#magic, #ranged` the ideal loc is the target loc itself; for `#melee`: `dirToTarget = calcDirXToTarget()` (+1 if target is to the right, -1 left, ties -> 1; `objAiCPU.txt:64-76`), `idealLocMod = attack.idealAttackLoc; idealLocMod[1] *= -dirToTarget; idealLocMod[2] *= -1; idealLoc = targetLoc + idealLocMod`. For the goblin sword `idealAttackLoc point(15,0)` -> stand 15 px on the near side of the target, same y.
- **Pathfinding is not grid/A***. `modPathFinding.findPathToLoc` (`modPathFinding.txt:50-63`) has two modes: `#beeline` = `moveToLoc(targetLoc)` straight at it (`modPathFinding.txt:97-105`); if the mover is stalled (`pMoveXY.getMoveVect() = point(0,0)`) for `pathFindingStallTime = 5` consecutive ticks (`updateStallCount`, `modPathFinding.txt:127-144`, params `modPathFinding.txt:21-22`) it switches to `#scenic`: picks a random waypoint `PointRoughly(myLoc, pPathFindingDistance = 100)` = my loc +/- up to 100 px on each axis (`modPathFinding.txt:65-73`, `PointRoughly()`/`VarRoughly()`: `var - slack + random(2*slack)`), walks toward it until stalled again, then back to `#beeline` (`modPathFinding.txt:107-125`). `pathFindingTime = 60` is dead (counter commented out).
- `moveToLoc(loc)` only stores `pMoveToLocTarget` (`modMoveToLoc.txt:355-359`); `modMoveToLoc.update` (`modMoveToLoc.txt:612-639`) calls `moveTowardsLoc` each tick and finishes when `GeomDistSqr(myLoc, target) <= 5*5` (`pMoveToLocArrivalDistance = 5`, `modMoveToLoc.txt:83`, `648-682`). In this build `pMoveTowardsLocFunction = #moveTowardsLocSpeed` (`modMoveToLoc.txt:119`; ghosts use the accelerated one): `moveVector = PointFrameMove(myLoc, targetLoc, pWalkSpeed); pMoveXY.setVect(moveVector)` (`modMoveToLoc.txt:449-477`), where `PointFrameMove` (`general_functions/PointFrameMove().txt`) returns the full remaining delta if `speed > dist`, else `distXY / (dist/speed)` -- i.e. a vector of length `walkSpeed` px/tick (4 for goblins) pointing straight at the target, overwriting the velocity every tick; `objMoveXY.update` then applies the walking friction before moving, so a goblin covers **2 px/tick** (corrected in Feedback round 2; `inertia` only affects knockback, section 6). `moveHorizReaction/moveVertReaction` set the facing flip and the walk animation. Nothing in the AI reads `walkType`.
- Tile collision applies to the AI's movement exactly as for the player (`pMoveXY.update` -> `pCallingPrg.checkCollisions(newLoc)`, `objMoveXY.txt:189-191`); a blocked move yields `moveVect = point(0,0)` which is what triggers `#scenic` wandering.

**When it attacks** (`targetInReach`, `objAiCPU.txt:350-415`):
- Melee (`targetInReachMelee`): `strikePointLeft = calcStrikePoint(-1)`, `strikePointRight = calcStrikePoint(1)` where `calcStrikePoint(faceDir) = myLoc + point(collisionLoc.x * faceDir, collisionLoc.y)` (`objAiAttack.txt:96-105`); in reach if either point is `inside(myTarget.getCollisionRect())`. For the sword: 15 px left or right of the goblin's reg point, same y, inside the target's collision rect.
- Ranged/magic/explode (`targetInReachRanged`): if `reach` is a point, `me.getLoc().inside(target.getRect().inflate(reach.x, reach.y))`; if an integer, `GeomDistSqr(myLoc, targetLoc) < reach*reach`. **Goblin archer: `reach 100`** -> fires when within 100 px of the target (reg-point distance). Player punch `reach point(7,10)` is a point but the player is not AI-driven.
- `attack()` (`objAiCPU.txt:33-40`, `objAiAttack.txt:37-54`): returns immediately if `getCooldownFin() = false`; non-magic attackers `faceTarget()` first; melee/ranged -> `pCharacterPrg.ensureMode(attack.animType)` (`#weaponMelee` / `#weaponRanged` -> plays that animation strip) and AI mode `#attack`; magic -> `chargeMagic()` (section 5).
- `updateAttack` (`objAiAttack.txt:389-414`): on the tick when the animation is on a fresh frame equal to `attack.animFrame` (`isOnAttackFrame`, `modAttack.txt:577-621`; `animFrame` may be a list) -> `performAttack()`; when the animation has looped once (`getAnimLooped`) -> `attackFin(#completed)` -> `clearTarget(); refreshTarget()` and back to `#findTarget`/`#moveToAttack` (`objAiCPU.txt:42-62`). So one attack = one full pass of the attack strip; the hit lands on frame `animFrame` (sword frame 7, bow frame 21, player punch frame 3).
- `performAttack` (`objAiAttack.txt:297-321`): aborts if the target is gone; melee -> `g.teamMaster.impactMeleeAttack(me.pCharacterPrg)` (section 4) + `playSound(attack.sound, attack.volume)`; ranged -> `performRangedAttack()` (section 4) + sound; then `pCharacterPrg.resetCooldown()`.
- **Cooldown**: `modWeaponManager.addCooldownCounter` (`modWeaponManager.txt:157-203`) creates per-weapon counters with `tim = [1, attack.cooldown]`, `fin = true` initially, and increment `inc = agility` for `#melee`, `dexterity` for `#ranged`, `mana_regeneration` for `#magic`; `updateCooldowns` steps every counter once per tick (`CounterOnce`, `modWeaponManager.txt:333-341`); `resetCooldown` resets the current weapon's counter (`modWeaponManager.txt:253-257`); `getCooldownFin` is its `fin` (`modWeaponManager.txt:207-211`). Ticks to ready ~= `cooldown / inc`. Goblin sword: `cooldown 0` -> ready the next tick (counter `[1,0]` finishes on the first step). Goblin archer bow: `cooldown 200 / dexterity 10` = **20 ticks** between shots (`Counter()` starts at `tim[1] = 1`, so ~20). Player punch `20 / agility 1` = ~19 ticks; energy blast `30 / mana_regeneration 30` = ~1 tick (the real limiter is charge time, section 5). `attackFin` does not reset the cooldown (commented out, `objAiAttack.txt:58`).
- After a hit the CPU character can enter `#look` (`objCPUCharacter.updateLook`, `objCPUCharacter.txt:249-274`): flips left/right `lookTimes = 4` times with `lookDelay = 10` ticks each, then `#walk`; entered from `#reelSit` (`modReel.txt:142-144`).

**Melee vs ranged differences**: the melee goblin has to reach an `idealAttackLoc` beside the target and hits by strike-point-in-rect; the archer stops as soon as it is within `reach 100` (it walks straight at the target until then, since its ideal loc is the target loc), then plays `#weaponRanged` and on frame 21 spawns a `goblinArrow` aimed at the target (with eyestrain error) -- see `performRangedAttack` in section 4. Both re-evaluate the target every 30 ticks and after every attack.

### Weapons

A character's current attack is a *copy* of a weapon's `#attack` list (`modWeaponManager.setCurrentWeapon`, `modWeaponManager.txt:305-317` -> `modAttack.setAttack` `modAttack.txt:813-847`). On `start`, `modWeaponManager.start` (`modWeaponManager.txt:53-63`) adds the character's own `#attack` as the "natural" weapon (`initNaturalAttack`, name `#punch` for the player; for goblins the natural attack is the bare struct default with `name #none`) and then `initStartingWeapon(params.weapon)` which pulls `g.actorMaster.getActorData(#goblinSword).attack` and makes it current (`modWeaponManager.txt:117-153`). So **goblins never instantiate the sword/bow as objects**; the `act_goblinSword`/`act_goblinBow` files are only data carriers (their `objType #objPowerUp` matters only when a weapon lies on the floor as a pickup). Attributes: `strength`, `dexterity`, `agility`, `eyestrain`, `mana_*` live in `modCharacterAttackProperties` (`modCharacterAttackProperties.txt:100-130` getters).

### Melee hit resolution (goblin sword, player punch)

On the attack frame, `performMeleeAttack` -> `g.teamMaster.impactMeleeAttack(attacker)` (`teamMaster.txt:1041-1123`):
1. `hatedTeams = calcTargetTeamsByAllegiance` -> `targetTeams = cullTeamList(hatedTeams[1])` (same `< 5 alive -> #none` rule as targeting). If `#none` is first and other teams exist, it falls back to `impactMeleeAttackOnTeam` over **every object in every hated team** (`teamMaster.txt:1083-1096`, `1125-1152`); otherwise it searches the unit map with `attackRad + 1` shells around the attacker's tile, `attackRad = calcAttackDist(tileSize)` = 0 for melee (`modAttack.txt:202-217`) -> candidates within 1 tile ring.
2. For each candidate (filtered by `hits` when it has one entry): `calcAttackHit(nObj)` -> for `#melee` `calcAttackHitMelee`: **hit iff `calcAttackLoc().inside(targetObj.getRect())`** (`modAttack.txt:287-303`), where `calcAttackLoc = myLoc + point(collisionLoc.x * facingDir, collisionLoc.y)` and `getRect()` is the sprite's bounding rect (`objGameObject.txt:500-504`, `SpriteGetRect`). Goblin sword: point 15 px in front of the goblin's reg point; player punch: `point(9,-1)`.
3. `collisionVect = calcCollisionVect(nObj)` -> `calcCollisionVectMelee` (`modAttack.txt:463-519`): when `power` is a point (all melee here): `collisionVect = calcAttackPower() * strength`, with `calcAttackPowerMelee = power with x * facingDir` (`modAttack.txt:359-371`). (`#magicMelee` uses `(strength + 1.5*manaCapacity)/1.5`; integer `power` would use `CollisionCalcVect`.)
   - Goblin warrior sword: `point(0.7,0) * strength 4` = **push (2.8, 0)** toward its facing; damage before inertia = 2.8 * damageMultiplier 2 = **5.6**.
   - Player punch: `point(2,0) * strength 8` = **push (16, 0)**; damage = 16 * 1 = **16** per punch (minus the victim's inertia scaling, below).
4. `CallPayloadFunction(attack.payloadFunction, nObj, collisionVect, attacker, owner)` -> `nObj.takeHit(collisionVect, attacker, owner)`.

### Ranged (goblin bow -> goblin arrow)

`performRangedAttack` (`modAttack.txt:721-811`) on the attack frame: `targetLoc = getTargetLoc()` (the AI target's loc; `#none` aborts), then **eyestrain**: `modifyLocWithEyestrain` (`objAiAttack.txt:268-288`): `percentOfRange = VarPercent(dist, [0, reach]); eyestrain = integer(VarValRange(percentOfRange, [0, eyestrain])); targetLoc += point(VarRoughly(0, eyestrain), VarRoughly(0, eyestrain))` -- i.e. a random offset in `[-e, +e]` on each axis where `e` scales linearly from 0 at point-blank to the character's `eyestrain` at `reach`. Archer: `eyestrain 5`, `reach 100` -> at most +/-5 px. Then `distXY = targetLoc - calcAttackLoc()` (`collisionLoc point(0,-2)` -> spawn 2 px above the archer's reg point) and, for `firingType #fullstrength`: `throwVect = distXY / (dist / strength)` = unit vector toward the target times **strength 8 px/tick**; (`#proportional` would be `distXY/10`). `pRangedVectOffset = 0` (`modAttack.txt:73`). The arrow is spawned with `g.actorMaster.newActor([typ: attack.bullet, startLoc: calcAttackLoc(), initVect: throwVect, useOffset: false])`, then `setTarget(myTarget)`, `setTargetLoc(targetLoc)`, `setTeam(archer's team)`, `setOwner(archer's owner)`. The bow's own `dexterity: 1` inside `#attack` is unused (cooldown uses the character's dexterity).

**Arrow flight** (`objBullet`, `objBullet.txt`): modules modAnimSet, modAttack, modExploder, modGrave, modRotational, modSplashDamage, modReincarnate, modRotator, modListNode (`objBullet.txt:27-35`); `collisionRectType #dynamic`, `rotational #once` (sprite rotated once to the velocity angle), starts in mode `#fly` (`objBullet.txt:71`). Per tick `updateFly` (`objBullet.txt:302-342`): `checkStalled` (moveVect below `stallSpeed point(2,2)` on both axes -> `#bulletLanded` -> `#land`); `checkCollisionWithTarget` (`objBullet.txt:87-112`): uses the `#target` relation (or, if none, `g.teamMaster.findTarget(me).obj` cached as `pRandomTarget`) and `CollisionCheck(me, myTarget)`; on hit: `collisionVect = calcCollisionVect(myTarget)` -> `calcCollisionVectBullet` = `calcAttackPowerBullet` = **`getVect() * attack.power`** (no splash: `splashDamageOn` default false, `modSplashDamage.txt:37`) = arrow velocity * 0.5 -> for a full-speed arrow (8 px/tick) a push of magnitude 4 -> damage `4 * damageMultiplier 3` = **12** (before the victim's inertia scaling). Then **both** `myTarget.takeHit(collisionVect, me.big, owner)` *and* `CallPayloadFunction(attack.payloadFunction = [#takeHit], ...)` are called (`objBullet.txt:317-320`), i.e. the hit appears to be applied twice (see Open questions). Arrows are affected by their own friction `point(5,5)` (5 %/tick speed loss, `objMoveXY.txt:172-177`) so they slow and eventually stall; `gravity = 0` in top-down. Bullets ignore tile collisions unless `gBulletsCollideWithBackground` (`objBullet.txt:114-126`; the global is not set in the exported scripts). Reaching `pTargetLoc` fires `#bulletArrivedAtTargetLoc` -> `#land` (`objBullet.txt:219-224`; via `moveToTarget` arrival, only used when a bullet is launched with `moveToTarget`; arrows use `initVect`, so they stall out instead). `#land` plays the `land` strip once then `setDead(true)` + `reincarnate()` (`objBullet.txt:278-283`). A bullet's own `takeHit` is ignored when landed (`objBullet.txt:267-273`). Experience: `attributeExperience` skips `lastAttacker` of type `#objBullet` (`modExperience.txt:111`).

### takeHit flow (victim side)

`takeHit(collisionVect, attackingObj, owner)` is dispatched through the class/module chain, outermost first:
1. `objCPUCharacter.takeHit` (`objCPUCharacter.txt:198-212`): ignored if ghost, or `pMode = #dead`, or already `checkDead()`; plays `hitByHairSound`; sets `pTakenHit`.
2. `objGameObject.takeHit` (`objGameObject.txt:781-788`): **inertia** -- `percent = 100 - pInertia; collideVect[1] = VarValRange(percent, [0, collideVect[1]]); collideVect[2] = ...; pMoveXY.vectAdd(collideVect)`, i.e. the push actually added to the velocity is `collisionVect * (100 - inertia)/100` (goblin warrior inertia 30 -> 70 %, archer 50 -> 50 %, player 0 -> 100 %). Because Lingo points are reference values modified in place, the modules below see the *scaled* vector.
3. Modules (`objModules.createModules`: each module's ancestor is the next, so all `takeHit` overrides run): `modReel.takeHit` (`modReel.txt:108-114`) -> `goDamageMode` -> `#reel` (section 6); `modEnergy.takeHit` (`modEnergy.txt:267-283`): skipped if the victim is in `#recoil` mode; otherwise `damage = (|v.x| + |v.y|) * attackingObj.getAttack().damageMultiplier` and `loseEnergy(damage)` if > 0. Note damage uses the **Manhattan length** of the (inertia-scaled) push and the *attacking object's* multiplier (for a bullet/spell that is the bullet's/spell's own attack copy).
4. `loseEnergy` (`modEnergy.txt:187-209`): if not invincible, `pEnergy -= amount; energyChanged()`; if `checkDead()` (`pEnergy <= pMinEnergy = 0`, `modEnergy.txt:80-85`): `outOfEnergy()`, `internalEvent(#outOfEnergy)`, `eventNotify(#outOfEnergy)`, `pEnergy = -100`, `pKilledInAction = true`; else `flickWhite()`; then `playSound(pTakeHitSound, pTakeHitVolume)` (goblins: none; player `"wizard_hit"` -- but see below).
- The **player** (`objPlayerMerlinCharacter`, ancestor `objCharacter`, `objPlayerMerlinCharacter.txt:23`) overrides `takeHit` (`objPlayerMerlinCharacter.txt:228-247`): ignored while `#die`; after the chain it forces `goMode(#walk)` (so the player is pushed but does not play a reel state), and if `checkDead()` -> `goMode(#die)` (+ respawn point with `modExtraLives`). `objPlayerCharacter.takeHit` (the older hair game) is **not** in Merlin's chain.
- Additional damage while reeling into walls: `objCPUCharacter.collisionWall/collisionVertical` (`objCPUCharacter.txt:103-127`) call `takeDamage(|speed|)` when in `#reel/#reel_fly/#reel_land`, and `takeDamage(amount)` only applies `amount - damageSpeed` if `amount > damageSpeed` (`modEnergy.txt:249-254`). This is where `damageSpeed` (3 for goblins, 5 default) is used -- a threshold on wall-impact damage, not on ordinary hits.
- Energy pools: `energy` (max = initial when `maxEnergy #auto`, `modEnergy.txt:45-49`); goblin warrior 100, archer 50, player 200. `getHealth()` = percent (`modEnergy.txt:109-115`). Passive regeneration: `recoverEnergy` (`modEnergy.txt:216-227`) +1 energy every `energyRecoverDelay` ticks (CPU 300, player 30) while alive and below max, called from `objCharacter.update` in most modes (`objCharacter.txt:299-329`). `mana_capacity/flow/burst/regeneration` are spell stats only (section 5); `energyIncPercentage` is the per-level energy gain (`pEnergyIncAmount = energy * energyIncPercentage / 100`, `modEnergy.txt:55`).
- `experienceImWorth` (warrior 2, archer 3): on `#outOfEnergy`, `modExperience.attributeExperience` (`modExperience.txt:99-118`) gives `experienceImWorth + experienceGained/2` to the `#lastAttacker` relation unless it is a bullet. **No script in the export ever sets the `#lastAttacker` relation** (grep over `script_objects/` and `master_objects/` finds only `modExperience` reading it), so in this build kills appear to award no experience -- see Open questions.

## 5. Energy blast

Data: `act_energyBlast.txt` is the **scroll pickup** (`objType #objScroll`, `AiType #objAiPowerUp`, `team #collectables`, `member energyBlast_scroll`, `collectSound "collect_powerup_01"`); its `#attack` list is what gets installed as a weapon named `#energyBlast` when collected (via `modWeaponManager.addWeapon`). `#character: #energyBlast` is the animation character name of the scroll. The spell projectile itself is a generic `act_spell` actor (`objType #objSpell`, `character #spell`, `friction point(0,0)`, `layerZ gGameBulletLayer`), created by `objAiAttack.ensureSpell` with `params.typ = #spell` (`objAiAttack.txt:157-188`) and given a *copy of the caster's current attack*, `chargeOffsetSide`, and team via `setSpellProperties` (`objSpell.txt:279-290`; also tints the sprite with `chargeColour rgb(255,200,0)`). `#bullet: #energyBlastBullet` is **not used** by energyBlast: bullets are only spawned by `modFireBullets` when `releaseFunction = #fireBullets` (`modFireBullets.txt:58-71`), and energyBlast keeps the default `releaseFunction #release`. There is no `act_energyBlastBullet` file. The **gmg\*** fields (`gmgChargeMax 15, gmgChargeSpeed 5, gmgChargeStart 5, gmgAutoFire true`) are the "golden machine gun" power-up variant: `modAttack.gmgOn/gmgOff` swap `pChargeMax/pChargeSpeed/pChargeStart/pChargeSpeedMax` (`modAttack.txt:849-861`), `objAiPlayer.internalEvent #spellCharged` auto-releases and re-charges when `gmgAutoFire` (`objAiPlayer.txt:83-89`), and `modAnimSet` switches to `#weaponMagic/#weaponMagicWalk` strips (`modAnimSet.txt:135-140`). Ignore for now.

**Charging** (player: mouse button held -> `objAiPlayer.interpretMouse` `#pressed` -> `playerAttackCharge()` -> `attack()` every tick, `objAiPlayer.txt:199-231, 265-289`; AI casters: `attackMagic`): `objAiAttack.attack` returns unless the cooldown is finished, then `chargeMagic()` (`objAiAttack.txt:126-130`): `pCharacterPrg.ensureMode(#charge)` (plays the `charge`/`chargeWalk` strip, `modAnimSet.txt:124-128`), `ensureSpell()` (creates the spell object at `calcChargeLoc()` = reg point + `chargeLoc point(0,-8)` mirrored by facing, `objCharacter.txt:113-120`, and sets the charge counter), then `chargeSpell()` (`objAiAttack.txt:132-142`): `currentSpell.charge(pChargeCounter.theCount, chargeLoc)` then `CounterOnce(pChargeCounter)`; when the counter finishes -> internal event `#spellCharged`. The charge counter runs from `calcAttackChargeStart()` to `calcAttackChargeMax()` by `calcAttackChargeSpeed()` per tick (`objAiAttack.txt:179-182`):

```
chargeMax   = min(pChargeMax, mana_capacity * chargeMaxModifier + chargeMaxBasic)   -- modAttack.txt:83-89
              if limitMagic: chargeMax = chargeMax * g.magicLimitMaster.getMagicLimit() / 100   -- modAttack.txt:94-100
chargeStart = min(pChargeStart + mana_burst, chargeMax)                               -- modAttack.txt:123-129 (chargeStartMax clamp if set)
chargeSpeed = pChargeSpeed * mana_flow   (capped by chargeSpeedMax unless #unlimited)  -- modAttack.txt:161-181
```
For the player with energyBlast: `chargeMax = min(999, 10 * 0.75 + 5) = 12.5` (at level 0; `mana_capacity` grows by `mana_capacityIncLevel .5` per level), times the magic limit percentage (`magicLimitMaster.getMagicLimit`, default `gMagicLimit`, set outside the exported scripts); `chargeStart = 0 + 1 = 1`; `chargeSpeed = 1 * 1 = 1` per tick. So a full charge takes ~12 ticks and the charge value `pCurrentCharge` is 1..12.5. The spell sprite is drawn at `size = pCurrentCharge * chargeSize (1)` px square (`objSpell.calcSize/updateSize`, `objSpell.txt:110-112, 303-308`) and re-aligned over the caster each tick (`align`: offset `-size/2` vertically for `chargeOffsetSide #top`, `objSpell.txt:75-108`). The spell object's `checkCollisions` returns the new loc untouched (no tile collision, `objSpell.txt:123-126`) and `checkDead` is always false. A `#chargeLimited` event from the spell can clamp the counter (`objAiAttack.txt:190-205`). Holding the button after the counter finishes just keeps calling `attack()` -> `chargeSpell()` with the counter pinned at max.

**Release**: player releases the mouse -> `playerAttackRelease` -> for `#magic`: `targetLoc = getTargetLoc()` = **`g.mouseMaster.getMouseLoc()`** (`objAiPlayer.txt:53-55, 291-302`) -> `releaseMagic(targetLoc)` (`objAiAttack.txt:337-350`): `pCharacterPrg.ensureMode(#release)` (plays `release`/`releaseWalk`), `releaseSpell(targetLoc)` -> `currentSpell.release(targetLoc, attack.spellSpeed)` -> `#spellReleased` -> `releaseNormal` (`objSpell.txt:228-248`): `moveToTarget([targetLoc, speed])` = `pMoveXY.moveToTarget` -> `setVect(GeomMoveVector(loc, targetLoc, speed))` (`objMoveXY.txt:265-270`), a straight-line velocity of `spellSpeed = 20` px/tick toward the release point, and plays `releaseSound "spell_release"` at a volume mapped from the charge (`VarMapRange(charge, [1,100], [10,255])`, `objSpell.txt:219-226`). The AI mode becomes `#release` until the release strip loops (`updateRelease`, `objAiAttack.txt:416-420`), and `resetCooldown()` (cooldown 30 / mana_regeneration 30 -> ready next tick). **So the player's blast is aimed at the mouse position, not at the nearest enemy**; `reach 9999` is only meaningful for AI casters (`targetInReachRanged`: fire from anywhere) and for eyestrain scaling. AI casters (e.g. goblin mage) release automatically on `#spellCharged` at `calcSpellTargetLoc()` = the target's loc (`objAiCPU.txt:78-100, 245-251`). The spell keeps the charge value (`pCurrentCharge`) it had at release.

**Flight and explosion**: the spell flies with `friction point(0,0)` (no slowdown), ignoring tiles and characters; `objMoveXY.finishConditionMet` (`objMoveXY.txt:102-132`) reports `#targetReached` when `PointArrivedAtTarget(loc, targetLoc, vect)` (passed the target on both axes in the direction of travel), which calls `moveXYfin` -> `goMode(#explode)` (`objSpell.txt:214-217`). The exported `objMoveXY.update` only carries the comment "pLoc can be adjusted by fin so as not to overshoot targetLoc" (`objMoveXY.txt:195`); no code that snaps the loc survives in the export, but the user remembers the explosion centred on the cursor, so the port places the spell on its target point before exploding (Feedback round 1). `objSpell.goMode(#explode)` (`objSpell.txt:145-161`): `explodeVolume = VarMapRange(pCurrentCharge, chargeVolumeMap.charge [1,100], chargeVolumeMap.vol [10,255])`; **`pCurrentCharge = pCurrentCharge * chargeExplodeFactor (4)`**; `startQuickFade()`; `g.teamMaster.impactAttack(me)` (= `impactMeleeAttack`, `teamMaster.txt:1037-1039`); `playSound(explodeSound "spell_explode", explodeVolume)`; sprite grows to the new size via `animUpdated`/`updateSize`. The explosion hit test (attack type `#magic`, `modAttack.txt:263-283`) and push (`modAttack.txt:523-567`):

```
splashRadius  = pCurrentCharge/2  (after x4)        -- 2 * charge at release
hit iff GeomDistSqr(spellLoc, targetLoc) < (splashRadius + targetRadius)^2,  targetRadius = target sprite width / 2 (objGameObject.txt:496-498)
speed = (splashRadius + targetRadius - SineDist(spellLoc, targetLoc)) * attack.power (0.75)
collisionVect = GeomMoveVector(spellLoc, targetLoc, speed)   -- vector of length `speed` from the explosion centre to the target (0 if speed <= 0)
```
A **direct hit** (target loc exactly on the explosion centre) would have no direction: `calcCollisionVectSpell` first nudges it with `if targetLoc = me.getLoc() then targetLoc = targetLoc + point(0,1)` (`modAttack.txt:545-547`) after `speed` was computed from `dist = 0`, so the victim is pushed **straight down (+y)** with the full `(splashRadius + targetRadius) * power` and takes full damage.
So damage falls off **linearly with distance from the centre** and scales with charge: at full player charge (12.5) the radius is 25 px + target radius; a target at the centre takes a push of length `(25 + r) * 0.75` and damage `= (|x|+|y|) * damageMultiplier (1)` after the victim's inertia scaling (e.g. a goblin warrior, r ~ 16: push up to ~31 * 0.7 = 21.5 -> damage ~ 15-22 depending on direction; both goblins die in a few full blasts; a charge-1 blast is 2 px radius + r, nearly harmless). Candidate victims come from the unit map within `attackRad + 1` shells, `attackRad = integer(pCurrentCharge / (2 * 32))` tiles (`modAttack.txt:207-208`), or all hated-team members when fewer than 5 enemies are alive (section 4). After the fade (`transBlendFin` -> `finish()`, `objSpell.txt:299-301`) the spell is gone. The player's `objSpell.finish` tells the player AI `chargingSpellFinished` (`objSpell.txt:52-62`). `explodeCharge` (10) is only for non-spell exploders (`modExploder`) and `objExplodingBullet`, not used here.

## 6. Reeling / knockback

- The push vector is the `collisionVect` computed by the attacker (section 4): melee = `power * strength` mirrored to the attacker's facing (so a sword hit always pushes horizontally away from the goblin, `power point(0.7,0)`); arrow = arrow velocity * 0.5 (direction of flight); blast = from explosion centre toward the victim with magnitude `(radius + r - dist) * 0.75`. It is scaled by `(100 - inertia)/100` and **added to the victim's velocity** (`pMoveXY.vectAdd`, `objGameObject.txt:781-788`).
- `modReel.takeHit` -> `goDamageMode` (`modReel.txt:50-61`): if the victim is already dead -> `#reel` as well; `recoil` (false for all here) would give `#recoil` instead. `goMode(#reel)` (`modReel.txt:78-80`) sets `frictionReel()` = `pMoveXY.setFriction(pFrictionReel)` = **`point(10,10)`** (`objGameObject.txt:387-389`) and resets the stall counter. Friction is a **percentage of the current speed lost per tick** (`objMoveXY.update`, `objMoveXY.txt:172-177`: `lostSpeed = PointValRange(pFriction, [0, speed]) * gGameSpeed; pVect = PointTowardZero(pVect, lostSpeed)`), so during a reel the velocity decays by 10 %/tick per axis (vs. the normal walking friction `point(50,50)`, `objGameObject.txt:41`), giving the knockback slide: push `v` travels roughly `v * sum(0.9^n)` ~ `9 v` px before stalling.
- **Reel duration**: no fixed timer. `updateReel` (`modReel.txt:161-168`) returns `getStalled()` = `pMoveXY.pStallCount.fin` (`objMoveXY.txt:244-246`); the stall counter (`tim [1,10]`, `inc gGameSpeed`, `objMoveXY.txt:58-60`) advances every tick where `|moveVect.x| + |moveVect.y| <= pStallSpeed` (`stallUpdate`, `objMoveXY.txt:365-387`; `stallSpeed 0.2` for characters) and resets otherwise -- i.e. the reel ends **~9-10 ticks after the character has effectively stopped moving**; the sword push of 2.8 * 0.7 ~ 2 px/tick decays below 0.2 in ~22 ticks, so a warrior reels ~30 ticks per sword hit; a player punch (16 px) keeps a warrior reeling ~40+ ticks. Each tick of `#reel` also fires `#updateReel` (used to keep a charging spell aligned, `objAiAttack.txt:248-253`). On finish: `#reelFinished` -> `goMode(#walk)` if alive (`modReel.txt:95-105`), `frictionNormal()` restores walking friction (`objCPUCharacter.goMode #walk`, `objCPUCharacter.txt:180-182`). `#reelFly/#reelLanded/#reelSit` (`sitTime 30`, `reelFinishSpeed 0.3`) are the side-on flavours; in the top-down build only `#reel` is entered. `reelProof true` would skip reeling entirely.
- While reeling, the AI is `#dazed` (`objAiCPU.characterModeChanged`, `objAiCPU.txt:116-135`) and does nothing; when the character leaves the dazed modes the AI goes to `#findTarget` (or continues an in-range attack via `unDaze`, `objAiCPU.txt:417-442`).
- Animation: `#reel` mode plays the character's `reel` strip (`anm_goblinWarrior_reel_02_01..04`, `anm_gar_reel_3_01..04`; the mode symbol *is* the strip name via `modAnimSet.getAnimSym`, `modAnimSet.txt:86-145`).
- **Tile collision applies during a reel**: the pushed velocity goes through the same `pMoveXY.update -> checkCollisions(newLoc)` path (`objMoveXY.txt:185-193`), and hitting a wall while reeling inflicts `takeDamage(speed)` = `speed - damageSpeed` if `speed > damageSpeed` (`objCPUCharacter.txt:103-127`, `modEnergy.txt:249-254`). `frictionStrong` = `point(20,20)` is used for `#recoil` only (`objGameObject.txt:395-397`).
- The player: pushed the same way (inertia 0 -> full vector), but `objPlayerMerlinCharacter.takeHit` immediately forces `#walk` (`objPlayerMerlinCharacter.txt:236`), so the player stays controllable; but `goMode(#walk)` restores walking friction only in `objCPUCharacter.goMode` (`objCPUCharacter.txt:180-182`), so in the export the player keeps `frictionReel` (10 %) from `modReel.goMode(#reel)` (Feedback round 1). The port does not copy that literally; see the remake decision under Feedback round 1.

## 8. Object-vs-object collision

- **Characters do not block each other.** There is no character-vs-character collision anywhere in the movement path: `objMoveXY.update` only calls `pCallingPrg.checkCollisions(newLoc)` which is the tile collision map (`objMoveXY.txt:189-191`, `modCollisionDetection`); `collisionMaster.checkCollisionsNewObject` is only used at spawn time (`actorMaster.txt:232-236`) and `collisionMaster` has no per-tick object pair test (handlers: `checkCollisions`, `checkCollisionsNewObject`, `checkLeaveScreen`, `constrainToPlayArea`, ... `collisionMaster.txt:15-167`). Enemies simply overlap the player; the melee AI stops at `idealAttackLoc` beside the target.
- **Bullets vs characters**: `CollisionCheck(obj1, obj2)` (`general_functions/CollisionCheck().txt:3-19`):
  ```
  obj1Rect = obj1.calcCollisionRect(obj1.getLoc()).rect
  obj2RectInfo = obj2.calcCollisionRect(obj2.getLoc())
  obj1Rect = obj1Rect + obj2RectInfo.edgeOffset       -- Minkowski-style: grow the bullet rect by the target's rect offsets
  return inside(obj2.getLoc(), obj1Rect)               -- test the target's reg point against the grown rect
  ```
  i.e. rect-overlap between the bullet's collision rect and the target's collision rect, evaluated as "target reg point inside bullet rect expanded by target rect". `calcCollisionRect` (`modCollisionRect.txt:97-113`) = `pCollisionRect + rect(loc, loc)`; `pCollisionRect` comes from the current frame's regPoint/width/height (`initRectFromCurrentImage`, `modCollisionRect.txt:54-84`), **clamped to `rect(-16,-16,16,16)`** (`pCollisionRectMax`, `modCollisionRect.txt:48`) and shrunk by 1 px (`inflate(-1,-1)`); it is recomputed every call for `#dynamic` rects (bullets, `objBullet.txt:46`), once for `#fixed` (characters). So a character's collision box is at most 32x32 around its reg point regardless of sprite size. Only the bullet's current `#target` (or a cached fallback target) is tested -- an arrow cannot hit a bystander (`objBullet.checkCollisionWithTarget`, `objBullet.txt:87-112`).
- **Melee** uses the strike *point* in the target's sprite rect (`getRect()` = full sprite rect, `objGameObject.txt:500-504`), and the AI's in-reach test uses the target's `getCollisionRect()` (`objAiCPU.txt:379-394`); **spell explosions** use circle-vs-circle with `targetRadius = sprite width/2`; none of them use `collisionLoc` as a point on the *victim*.
- Spawn-time check `collisionMaster.checkCollisionsNewObject` prevents creating a non-`createOnSolid` object over hard edges; the objects-layer goblins spawn at tile centres, so this only matters for hand-placed tiles over walls.

## Open questions

- **Double hit from bullets** (resolved in Feedback round 1: ported as two hits).
- **Experience is never attributed**: `#lastAttacker` is read by `modExperience.attributeExperience` but no exported script sets it (`formRelationship(..., #lastAttacker)` does not occur). Either it lives in an unexported script, or kills give no experience in this build (`experienceImWorth` would then be dead data). Stars (`modStarReleaser`, `objStar`, `g.starMaster.experienceStar`) are released on the *player's* level-up (`modExperience.levelUp`, `modExperience.txt:201-211`), not on enemy death, so they are not entangled with the death path.
- **`VarRoughly` range**: `VarRoughly(var, slack)` = `var - slack + random(2 * slack)` and Lingo `random(n)` returns `1..n`, so the result is in `[-e+1, e]` (asymmetric), not `[-e, e]`. The port's `roughly` uses the symmetric `[-e, e]`; eyestrain and scenic waypoints are affected by one pixel on the negative side.
- `gGameSpeed`, `gMagicLimit`, `gBulletsCollideWithBackground`, `gExitArrows`, `gNavMode`, `gGameName` are set outside the exported casts (main movie script); all timing above assumes `gGameSpeed = 1`.
- Whether Lingo points passed to `takeHit` are modified in place (assumed yes: the code `duplicate()`s points defensively everywhere), which decides whether damage uses the inertia-scaled or raw push. If not in place, damage ignores inertia and only the knockback is reduced.
- The goblin `grave` member for the warrior: no `anm_goblinWarrior_grave_*` frame is exported; `goblin_grave.bmp` under `gfx/goblinArcher/` is presumably registered in-cast under both names (space-separated member name). If absent, `getAnimLooped` for a missing strip falls back to `#stand` and the grave blit would use the stand frame.
- `getRect()` (full sprite rect) vs `getCollisionRect()` (clamped 32x32): the melee hit test and the AI in-reach test use different rects, so a goblin can decide it is in reach (collision rect) yet `calcAttackHitMelee` tests the sprite rect -- always a superset, so no missed hits, but the port should pick one.
- `damageSpeed` is only a wall-impact damage threshold in this build; confirm no other use before exposing it as "damage speed".
- The `< 5 enemies alive` switch between full-team scan and unit-map shell search changes only performance, not results, except that the shell search stops at the first non-empty ring (nearest by tile ring, then by distance within the ring), which can differ slightly from true nearest.

## Port decisions

Choices the remake made where the engine is ambiguous, depends on values outside the exported casts, or was simplified on purpose. Each is local to the file named.

- **Two takeHits per arrow.** `objBullet.updateFly` calls `takeHit` and then the `#takeHit` payload function for the same collision; the port applies both (`src/sim/tick-combat.ts`, `stepBullets`), i.e. 24 damage and a push of 8 for a full-speed arrow on the player (Feedback round 1).
- **No experience.** Nothing in the exported scripts sets `#lastAttacker`, so kills award nothing; `experienceImWorth` is carried in `ActorDef` but unused, and there are no level-ups or stars.
- **`LANDED_TICKS = 30`.** A landed arrow stays 30 ticks before removal (`src/mr-open/mr-bullet.ts`); the engine removes it once its one-frame `land` strip has played.
- **Magic limit fixed at 100 %.** `gMagicLimit` is set outside the export; `chargeLimits` takes the percentage as a parameter with default 100 (`src/mr-open/mr-spell.ts`), so the player's blast charges 1..12.5.
- **Energy blast granted via tuning.** The original gives the blast through the `energyBlast` scroll pickup; pickups are not ported, so `assets/tuning.json` sets `player.weapon = energyBlast`.
- **Full-scan targeting.** `findTarget` always scans every hated-team member for the nearest one (`findATarget`); the engine's unit-map shell search for 5+ enemies, which can pick a slightly different target by tile ring, is not ported (`src/mr-open/mr-targeting.ts`).
- **Arrows ignore tiles.** `gBulletsCollideWithBackground` is not in the export; the user confirmed from the original that arrows fly through walls. They still slow by friction, stall, land and hit characters.
- **Counters use N-tick timing.** Lingo counters start at 1 and finish on reaching their length, one step earlier than a plain countdown; cooldowns, retarget and path-stall counters and reel stall counts here are "ready after ceil(length / increment) ticks" (`src/mr-open/mr-attack.ts`, `mr-ai-cpu.ts`, `mr-pathfinding.ts`, `mr-take-hit.ts`). Most shipped values give the same tick; a few are one tick later.
- **Nav mode with the engine default 6.** `gNavMode` is set outside the export and taken as on: in a cleared room the player walks with `navModeAcceleration` 6 (modNavMode default) instead of `walkAcceleration` 2, a steady 6 px/tick under 50 % friction.

## Feedback round 1

- **Landed arrows stop.** `objBullet.goMode(#land)` does `setVect(point(0,0))` before `internalEvent(#land)` (`objBullet.txt:207-209`); the port had kept the sub-2 px/tick stall velocity decaying by friction, so landed arrows drifted. `stepBullets` now zeroes the velocity on landing.
- **Energy blast explodes on its target point.** `objMoveXY.update` has the comment "pLoc can be adjusted by fin so as not to overshoot targetLoc" (`objMoveXY.txt:195`) but no snapping code survives in the export; the user remembers the explosion centred on the cursor, so the port ports the intent: on arrival the spell is placed on `targetPoint` (the mouse point for Space/click, the chosen point for E/F) before the splash is computed.
- **Archer weapon technique (-75).** `modWeaponTechnique.update` runs `updateWeaponTechnique` every tick the AI is in `#attack` (`modWeaponTechnique.txt:121-143`): a counter (`tim [1,1]`) finishes every other tick, each finish adds `weaponTechnique` to `pWeaponTechniqueCache`, and while the cache is below `-pFrameValue` (-100) `addFramesForWeaponTechnique` (`modWeaponTechnique.txt:33-42`) calls `frameExtendDelay(1)` -> `objAnimStrip.extendDelay` (`objAnimStrip.txt:52-60`: current frame's `tim[2] + 1` and the delay counter restarts), lengthens the technique counter by one tick and adds 100 back. The cache and counter persist across attacks. Only the archer has a non-zero technique among ported actors; for -75 that is about three extra ticks per ten, so its 21-tick bow strip takes ~32 ticks (the shot on frame 21 comes ~31 ticks after the draw starts instead of 20) and the archer stands still that much longer per shot. The port had ignored the module. Nothing else slows the archer after a shot: `runReload` is false for goblins (`objCPUCharacter.txt:30`), `#look` (`lookTimes 4`, `lookDelay 10`) is only entered from the side-on `#reelSit` (`modReel.txt:144`), and walking is `walkSpeed` 4 px/tick (`act_goblinArcher.txt:17`) whenever it is out of reach. Positive techniques (frame skipping) are not ported. Implemented in `src/mr-open/mr-weapon-technique.ts`, applied after the animation step (`extendFrame` in `src/sim/anim.ts`).
- **Enemy reorientation is modPathFinding's `#scenic` detour, not a timer.** The only random movement in the enemy AI is `goPathFindingMode(#scenic)`: `PointRoughly(myLoc, 100)`, a waypoint up to 100 px away on each axis (`modPathFinding.txt:65-73`). It is entered when the walker's actual move vector has been (0,0) for the stall count (`pathFindingStallTime 5`, `updateStallCount` `modPathFinding.txt:127-144`: blocked by a wall, or standing on a goal that is not in reach), and left only on another stall (`updateScenic` `modPathFinding.txt:107-125`), i.e. after reaching the waypoint and standing there for the stall count, or on hitting a wall. `#arrivedAtAttackLoc` resets only the stall counter and stops the walk (`modPathFinding.txt:79-81`); the path mode and waypoint persist through attacks, reels and retargets. So an enemy that was on a detour when it came into reach attacks, and when its target is out of reach afterwards it walks on to the old waypoint, stops there briefly, then beelines to the (re-evaluated) nearest target -- which is probably what the user remembers after a missed swing. There is no chance per attack or per second: `pathFindingTime 60` is dead (its counter is commented out, `modPathFinding.txt:118-122`), no `random()` exists in `objAiCPU`/`objAiAttack`/`objCPUCharacter`, and `#look` (`lookTimes 4`, `lookDelay 10`, `objCPUCharacter.txt:27-28, 249-274`) is only entered from the side-on `#reelSit` (`modReel.txt:144`). The port had reset the path to beeline on reaching attack range and left `#scenic` the moment the waypoint was reached; both now follow the engine (`src/mr-open/mr-pathfinding.ts`, `src/sim/tick-ai.ts`).
- **Merlin's hit response.** The whole player path is `objPlayerMerlinCharacter.takeHit` (`objPlayerMerlinCharacter.txt:228-241`) -> `objGameObject.takeHit` (inertia 0: the full push is added, `objGameObject.txt:781-788`) -> modExperience -> `modReel.takeHit` -> `goDamageMode` -> `goMode(#reel)` -> `frictionReel()` = `point(10,10)` (`modReel.txt:50-80`, `objGameObject.txt:387-389`; the player has no `frictionReel`/`reelProof`/`recoil` override) -> modEnergy damage; then `goMode(#walk)`. Only `objCPUCharacter.goMode(#walk)` calls `frictionNormal` (`objCPUCharacter.txt:180-182`); `objCharacter.goMode` does not (`objCharacter.txt:188-222`) and no other script restores the player's friction (grep: `frictionNormal` is otherwise only in modProp's cutscene prop modes). So in the exported engine Merlin loses 10 % of his speed per tick instead of 50 % from his first hit on: a sword push of 2.8 slides him ~25 px instead of ~3 px, and **as a side effect his steady walking speed becomes 9 x acceleration** (18 px/tick at walkAcceleration 2; nav mode's 6 is capped by `gMoveSpeedLimit` at 31 px/tick). **Remake decision:** the shipped game cannot have let Merlin walk at 18 px/tick after a hit, so the restore must live outside the export. The port keeps the long slide but not the speed-up: the player's push goes into a separate `knockback` vector that decays by `frictionReel` (10 %/tick) while his walking velocity keeps normal 50 % friction (`applyHit`, `stepPlayerMove`). `player.frictionReel` in `assets/tuning.json` tunes the slide length. The goblin sword uses the same numbers for every victim (`power point(0.7,0) * strength 4`, damageMultiplier 2); `#weight` (player 0.2) only scales gravity, which is 0 top-down (`objMoveXY.txt:175`).
- **Arrows hit twice.** `objBullet.updateFly` (`objBullet.txt:317-320`) calls `myTarget.takeHit(collisionVect, ...)` and then `CallPayloadFunction(attack.payloadFunction, ...)`; the arrow's payload is the struct default `[#takeHit]` (`structMaster.txt:193`; `act_goblinArrow` does not override it) and `CallPayloadFunction` calls `takeHit` again with the same point (`general_functions/CallPayloadFunction ().txt`). So the victim gets two pushes and two damage applications; the second sees the vector already scaled by its inertia, since `objGameObject.takeHit` writes the scaled values into the caller's point. Melee and spells go through `CallPayloadFunction` only (`teamMaster.txt:1120, 1146`), once. The port applies both arrow hits.
- Aside: `modExperience.takeHit` does set `#lastAttacker` (`modExperience.txt:300-310`), so the Open question that nothing sets it is wrong; experience is still not ported.

## Feedback round 2

- **CPU walkers move at half their walkSpeed.** Each game object's `pMoveXY` is a separate entry in the global updater (`objGameObject.start`, `objGameObject.txt:773-779`: `setAutoUpdate(true); calcStart(); setAutoUpdate(false)`, so it is added right after the object itself). The object's own update runs its modules, including `modMoveToLoc.update` -> `moveTowardsLocSpeed` -> `pMoveXY.setVect(PointFrameMove(loc, target, walkSpeed))` (`modMoveToLoc.txt:449-477`, `612-639`). Then `objMoveXY.update` (`objMoveXY.txt:160-203`) runs: `pAdjustXY` is true for every game object (`initGameChar`, `objMoveXY.txt:69-78`), so it first calls `pCallingPrg.updateAI()` (`objCPUCharacter.updateAI` -> `objAiGameObject.updateAI` -> `pAI.update`, i.e. objAiCPU with modPathFinding, which only stores a new `moveToLoc` target), and **then** takes friction off `pVect` (`PointValRange(pFriction, [0, speed]) * gGameSpeed`) and moves by what is left. Walking friction is `point(50,50)`, so the 4 px/tick walk vector moves the goblin 2 px/tick. Whichever of the two updater entries runs first, the move always sees a walk vector with one friction step applied. `gGameSpeed` is never assigned in the export (taken as 1, as for the animation delays); weapon technique only stretches attack frames; nothing ties walk speed to the walk animation. The port now applies friction to walking characters in `stepMovement` like everything else; the old claim that walking bypasses friction was wrong.
- **Character collision rects are fixed.** `modCollisionRect` defaults `collisionRectType #fixed` (`modCollisionRect.txt:34`); `calcCollisionRect` computes the rect from the current image only while `pCollisionRect = #none` or for `#dynamic` (`modCollisionRect.txt:100-102`). Only `objBullet` sets `#dynamic` (`objBullet.txt:46`). The first call happens on the first `checkCollisions` in `objMoveXY.update`; at that point the character is in its `initMode #stand` and `getMoving()` is false (the AI has only just stored a move target, `modMoveToLoc.update` sets the moving flags on the next object update), so `getAnimSym` gives `#stand` (`modAnimSet.txt:86-118`) and the rect comes from the stand frame. The port had recomputed every character's rect from the current strip, so the 27 px wide warrior sword frame widened the rect from 13 to 25 px; on the tick a warrior walks off after a swing (movement runs before the strip changes back) a warrior with its back flush against a 1-tile wall overlapped the wall by 6 px and the push-out against its walking direction carried it through. Characters (and spells) now keep the rect of the strip they are created with (`stand` for characters); bullets stay dynamic.
- **Arrow hitbox (remake).** `collisionRectScale` (ActorDef, default 1) scales the collision rect about the reg point; `goblinArrow` uses 0.5 (user request, `assets/tuning.json`).
- **Earlier stuck detour (remake).** `pathFindingStallTime` is now an ActorDef field (engine default 5, `modPathFinding.txt:22`); goblin warriors and archers use 2 (user request).
- **Random spreading detour (remake, not in the original).** After a CPU character's melee attack strip ends, and after every `detourMoveTicks` (90) ticks of continuous walking, it rolls `detourChance` (0.15, seeded RNG). On success it stands for `detourPauseTicks` (15), then walks toward a point `detourDistance` (50 px) away in a random direction at its walk speed, until within the modMoveToLoc arrival distance (5 px) or stalled for `pathFindingStallTime` ticks (tile collisions apply), then retargets the closest enemy on the same tick (AI modes `detourPause`/`detourMove`, `src/sim/tick-ai.ts`). A hit cancels the detour. `detourChance` 0 disables it.
- **Angular spread (remake).** Two seeded random rotations on top of the engine: a fired bullet's velocity turns by a uniform angle in [-`projectileSpreadDeg`, +`projectileSpreadDeg`] of the shooter (on top of eyestrain's aim error; `goblinArcher` 5), and each spell explosion push turns by a uniform angle in [-`knockbackSpreadDeg`, +`knockbackSpreadDeg`] of the caster (`player` 3), magnitude unchanged (`spreadVec`, `src/sim/rng.ts`). Both default to 0, which draws nothing and keeps the engine's behaviour and random sequence.
