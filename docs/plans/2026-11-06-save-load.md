# Save and load: implementation plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Autosaves per map (written on each room clear and loaded on death or Continue), two
best-score tables (with and without loading), and an Advanced settings fold.

**Architecture:** A save is the debug sim snapshot (`src/debug/sim-snapshot.ts`) plus a `loaded`
flag. A small pure store module (`src/data/saves.ts`) holds the saves in localStorage under
per-map keys, and an index keeps them capped at MAX_SAVES. `main.ts` writes a save when the sim
reports a room clear. It restores a save the way `mr.loadState` already does (`restore(deserializeSim(...))`),
on Continue and after the game over sequence. Scores route through `best-scores.ts` with a
second table.

**Tech Stack:** TypeScript, Vitest, pnpm, localStorage (`FavouritesStore`, the storage interface
best-scores.ts already uses).

Design (all owner decisions): `docs/plans/2026-11-06-save-load-design.md`. Rules: `CLAUDE.md`.

Run every command with this shell prefix:
`export PATH="$HOME/.nvm/versions/node/v22.17.1/bin:$HOME/Library/pnpm:$PATH" && set -o pipefail`.

### Task 1: The save store (`src/data/saves.ts`)

**Files:**
- Create: `src/data/saves.ts`, `src/data/saves.test.ts`

**API:**
- Keys: `mr-remake.save.<mapId>`, plus an index key `mr-remake.saves` holding `{ mapId, writtenAt }[]`.
- Functions:
  - `readSave(store, mapId): MapSave | null`
  - `writeSave(store, save: MapSave): void`
  - `dropSave(store, mapId): void`
  - `savedMapIds(store): Set<string>`
- `MapSave` is `{ snapshot: SimSnapshot; loaded: boolean }`, stored as one JSON string.
- `writeSave` refreshes the index entry. With more than `MAX_SAVES` (20) entries, it drops the
  oldest `writtenAt`.
- If `setItem` throws (quota), drop the oldest other save and retry once, then give up quietly.
- Every read is guarded with try/catch, as best-scores.ts does.
- A save with a different `SNAPSHOT_VERSION`, or that does not parse, reads as `null` and is
  dropped.
- Keep `writtenAt` injectable (a parameter), so the tests are deterministic.

**Steps:**
1. Write the failing tests with an in-memory store (see how `best-scores.test.ts` fakes it):
   - Round-trip a save.
   - `dropSave` removes it.
   - The cap drops the oldest.
   - A wrong version reads null and is removed.
   - Quota failure: a store that throws once still ends with the new save written.
2. Implement, run `pnpm test src/data/saves.test.ts`, then commit.

### Task 2: Two best-score tables

**Files:**
- Modify: `src/data/best-scores.ts` and its test

**Rules:**
- The existing `BEST_SCORES_KEY` table becomes "no loading". Add `WITH_LOADING_BEST_SCORES_KEY`.
- `loadBestScores` returns `{ noLoading, withLoading }`. When the with-loading key is missing,
  the migration copies `noLoading` into it.
- Replace `withRunScore(bests, mapId, mode, score)` with
  `withRunScore(bests, mapId, mode, score, loaded: boolean)`. It updates `withLoading` when beaten,
  and also `noLoading` when not `loaded` and beaten. It returns null when nothing changed.
- Reset scores clears both tables.

**Steps:**
1. Write the failing tests: the migration copies the old table; a loaded run never touches
   `noLoading`; a no-load run updates both; the old rooms-only key still migrates.
2. Implement, then fix the callers (`grep -rn "withRunScore\|loadBestScores\|BestScores" src`),
   with `loaded` false for now.
3. Run `pnpm test` and `pnpm tsc --noEmit`, then commit.

### Task 4: Autosave and Continue in main.ts

**Files:**
- Modify: `src/main.ts`, `src/ui/maps-panel.ts` / `src/ui/map-browser.ts` (the saved mark and
  the choice), `src/ui/pause-menu.ts` (Restart map drops the save)
- Possibly create: `src/ui/continue-choice.ts` (the Continue / New game overlay)

**Rules:**
- **When to save.**
  - Find where the sim reports a room clear. The score banks on a clear, so look at how
    `src/sim/score.ts` or the events signal it; add an event if there is none, e.g. `roomCleared`
    in `sim.events`.
  - After a tick with a room clear, if Auto-save is on and the map is not a roguelite floor
    (`world.map.markExit` or the roguelite map id), call `writeSave` with
    `snapshotOf(sim, { mapId, seed, dataHash, inputs: [] })` and the run's `loaded` flag.
  - This covers the map-complete tick too.
- **Continue / New game.**
  - When a map with a save is opened, show "Continue" / "New game" first.
  - Reuse the overlay and menu-list helpers the pause menu and run summary use (`menuList`,
    WASD/Enter).
  - Continue restores the save as `mr.loadState` does (`restore(deserializeSim(...), seed)`). For
    a generated map, the layout is rebuilt from the save's seed first; read how `reloadOnMap` and
    the generated-map seed flow work. The run then counts as loaded.
  - New game drops the save and starts as now. Restart map in the pause menu also drops it.
- **Death.** In the game-over path (`restartDue(ending)` in main.ts, two places), if a save
  exists for the map, restore it (the run counts as loaded); otherwise call `restart()` as now.
- **Scores.** Keep a `runLoaded` flag beside the run, and pass it to `withRunScore`.
- **Stale saves.**
  - A save whose snapshot names an actor def missing from `defs`: catch the `deserializeSim`
    error, or check up front, then drop the save and show a short notice (reuse an existing
    toast or hint element if one exists; otherwise a line in the choice overlay).
  - A `dataHash` mismatch still loads (console.info only).
- **The map list** marks saved maps (`savedMapIds`), e.g. a small "saved" tag.

**Steps:**
1. Tests for the pure parts:
   - Extract the decision "what happens after the game over" as a small pure function
     (`afterGameOver(save | null) => 'load' | 'restart'`) and the "should autosave" rule
     (`shouldAutoSave({ autoSave, markExit, mapId })`) into a testable module.
   - Test them, including that a roguelite floor never saves.
   - Add a sim-level round-trip test: run a test map until a room clears, snapshot, deserialize,
     compare key state. Follow `src/debug/sim-snapshot.test.ts`.
2. Implement the wiring, then run `pnpm test`, `pnpm tsc --noEmit` and `pnpm build`.
3. Run `pnpm dev` on a spare port (not 3371, the owner's) for a manual check:
   - Clear a room on `?map=test_maps/combat_test`, reload, choose Continue, die, and check the
     save loads.
   - Take one or two screenshots only if your tooling works; always launch headless Chrome with
     `--mute-audio`.
4. Commit.
